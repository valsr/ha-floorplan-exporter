# Focus Box Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write each floor's focus box (the pixel rectangle of its images the walls occupy) in `manifest.json`, computed from the walls and the camera, or set by hand per floor.

**Architecture:** A pure `plan/FocusProjector` projects wall corners through the same pinhole camera the Blender GPU renderer builds; `engine/HomeInspector` supplies the corners; the `Exporter` picks the manual box or the projected one per floor and `ManifestWriter` writes it. The manual box and the margin travel through `Instructions` → `ExportConfig` like the camera does, and the dialog edits them.

**Tech Stack:** Java 8 (src/main), Sweet Home 3D 7.5 API, Swing, JUnit 5 via `scripts/test.sh`.

**Spec:** `docs/superpowers/specs/2026-10-21-focus-box-design.md`

## Global Constraints

- `src/main` compiles for Java 8: no `var`, records, `List.of`, text blocks.
- Only `engine` and `plugin` may use Sweet Home 3D classes; `plan` stays free of them.
- File formats: `"focus": {"x": [left, right], "y": [top, bottom]}`, integer pixels; `"focusMargin"` a number 0–50, default 5; manifest floor `"focus"` adds `"source": "manual" | "auto"` or is `null`.
- Manifest key order: `focusMargin` right after `exposure`; floor `focus` right after `camera`.
- Rounding of a computed box: left/top `floor`, right/bottom `ceil`, after the margin, then clip to `[0, width]` × `[0, height]`.
- Existing behaviour and the 129 existing tests stay green.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A camera looking straight down (pitch π/2): the projection must not divide by zero or flip axes — covered by `FocusProjectorTest.topCameraOrientation`.
- Instructions with `"floors": "*"` and a `focusMargin`: must load and export with computed boxes for every floor — covered by `InstructionsResolverTest.allFloorsUseComputedBoxes`.
- Changing width/height in the dialog after setting a manual box: Export must be blocked, not export a box outside the image — covered by `ExportDialogTest.manualBoxLargerThanImageIsAnError`.
- Loading old instructions without `focus`/`focusMargin` (every existing file): must load as before with margin 5 — covered by `InstructionsJsonTest.defaultsWithoutFocus`.
- A floor whose walls are all on another level (or no walls): `focus` must be `null`, not an exception — covered by `ExporterTest.floorWithoutWallsHasNullFocus`.

- [ ] **Step 3: Implement `FocusBox` and `FocusProjector`.** The vectors are the GPU renderer's (`BlenderRenderer.createRenderCommand`), in Sweet Home 3D's 3D frame `(planX, elevation, planY)`:

```
cam = (x, z, y)
f = (−sin yaw·cos pitch, −sin pitch,  cos yaw·cos pitch)
u = (−sin yaw·sin pitch,  cos pitch,  cos yaw·sin pitch)
r = f × u                       // the worker's right = forward × up
k = (width/2) / tan(fov/2)
for corner (px3 = (cx, elev, cy)) : d = p − cam; zc = d·f; if zc <= 1e-6 → return null
    sx = width/2 + k·(d·r)/zc ;  sy = height/2 − k·(d·u)/zc
box = min/max of sx, sy; widen by margin% of its own width/height; floor/ceil; clip; empty → null
```

Expected: all pass. If `topCameraOrientation` fails on a sign, fix the formula, not the test: the test encodes the renderer's own frame (yaw 0, top view ⇒ plan rotated 180°).
