# Light Cap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An export option, `capLight`, that keeps hidden ceilings and hidden levels in the rendered scene as light blockers the camera cannot see, so light enters a floor only through its windows and openings.

**Architecture:** The Blender GPU renderer gains a rendering parameter, `hiddenItemsBlockLight`; when set, its scene exporter also writes hidden ceilings and the items of hidden levels as `occluder<N>` objects, and its Blender worker hides those from camera rays. The exporter detects the parameter in a renderer's resource bundle, asks for it through system properties for the life of a render session, and carries the choice through the instructions file, validation, manifest and dialog.

**Tech Stack:** Java 17 + Python (Blender 4 `bpy`) in `/work/sh3d/gpu-renderer`, built with `make`; Java 8 source level + JUnit 5 in `/work/sh3d/ha-floorplan-exporter`, built with `scripts/`.

**Spec:** `docs/superpowers/specs/2026-10-07-ha-floorplan-exporter-design.md`, §11.

## Global Constraints

- Two repositories. Tasks 1–2 are in `/work/sh3d/gpu-renderer` on a new branch `hidden-items-block-light`; tasks 3–5 are in `/work/sh3d/ha-floorplan-exporter` on branch `light-cap`. Nothing is pushed or merged without asking.
- GPU renderer: with the parameter `false`, the exported `scene.obj` and `scene.json` are exactly what they are today. The home given to the renderer is never modified. Follow that repo's style (2-space indent, `Check`-based test classes with a `main`, comments in its voice).
- Exporter: every Global Constraint of `docs/superpowers/plans/2026-10-07-ha-floorplan-exporter.md` still holds, in particular `--release 8` and no reference to `sh3d.gpurenderer` classes in `src/main` (the class name may appear only in messages and tests).
- Parameter name, exact: `hiddenItemsBlockLight`; system properties `<rendererClassName>.lowQuality.hiddenItemsBlockLight` and `<rendererClassName>.highQuality.hiddenItemsBlockLight`; values `true` / `false`.
- Occluder objects are named `occluder0`, `occluder1`, … in the OBJ file.
- JSON key `capLight`, default `false`. Dialog label `Block light through hidden ceilings and levels`.
- The reference re-render must not write into `/media/nas/files/Home/floorplan`; use `--output` to a scratch folder.

## Review Focus

1. **Home with a single level or none**, `capLight` on: only hidden ceilings become occluders; no error. (Task 1)
2. **A level the user marked not viewable** stays out of the scene entirely, cap or not. (Task 1)
3. **Cap on, ceilings not hidden** (`hideCeilings` false): ceilings are exported once, as normal visible objects, not twice. (Task 1)
4. **An export that fails mid-session** must still restore the system properties, or Sweet Home 3D's own photo dialog would keep rendering capped. (Task 3)
5. **An older `gpu-renderer.jar`** without the parameter: the renderer is listed, the cap shows as unsupported, nothing throws. (Task 3)

### Task 1 (gpu-renderer): export hidden items as occluders

**Files:**
- Modify: `src/main/java/sh3d/gpurenderer/SceneExporter.java`, `src/main/java/sh3d/gpurenderer/BlenderRenderer.java`, `src/main/resources/sh3d/gpurenderer/BlenderRenderer.properties`
- Test: `src/test/java/sh3d/gpurenderer/SceneExporterTest.java`, `src/test/java/sh3d/gpurenderer/TestHomes.java`

**Interfaces:**
- Produces: `static Map<String, Object> SceneExporter.export(Home home, Object3DFactory object3dFactory, File folder, boolean hiddenItemsBlockLight)`. The existing three-argument `export` stays and passes `false`.
- Produces: `BlenderRenderer.properties` keys `lowQuality.hiddenItemsBlockLight=false`, `highQuality.hiddenItemsBlockLight=false`, with a comment line like the existing one. `BlenderRenderer.render` passes `Boolean.parseBoolean(getRenderingParameterValue("hiddenItemsBlockLight"))` to `SceneExporter.export`.
- Produces: in `scene.obj`, groups named `occluder<N>` written after the visible items and before `ground`.

Algorithm for the occluders (the signature and tests do not determine it):

```
copy = home.clone()                       // ids are kept, so items match by id
for each level of copy that is viewable:  level.setVisible(true)
for each room R of home:
  C = room of copy with R's id
  if R's level is null or viewableAndVisible:
     if R.isCeilingVisible(): C is not an occluder
     else: C.setCeilingVisible(true); C.setFloorVisible(false); C is an occluder   // ceiling alone
  else if R's level is viewable: C is an occluder (as it is in the home)
every other exported item (same filter as getExportedItems, applied to copy)
  whose level in home is viewable but not visible: its copy is an occluder
write each occluder with object3dFactory.createObject3D(copy, item, true)
```

Building from the clone keeps wall joins and floor openings right, since Sweet Home 3D computes a wall's or a room's geometry from the other items of the home it is given. Occluder lamps add no light and occluder rooms no ceiling light: `lights`, `emissiveMaterials` and `opaqueMaterials` are computed from `home` exactly as today.
